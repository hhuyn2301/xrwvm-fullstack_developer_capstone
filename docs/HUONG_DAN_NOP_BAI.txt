1. CHẠY NHANH ỨNG DỤNG

Giải nén Dealership_Capstone_Source.zip và mở terminal trong thư mục dự án.
Cần Docker Engine + Docker Compose v2 và Python 3.

   python3 scripts/create_env.py
   docker compose up --build

Mở:
   Django + React: http://localhost:8000
   Express API:   http://localhost:3030
   Sentiment API: http://localhost:5050

Tạo tài khoản quản trị của bạn:
   docker compose exec web python manage.py createsuperuser --username root

Đăng ký tài khoản người dùng qua /register để thực hiện các bước login/review.
Không có tài khoản admin mặc định hay mật khẩu production dùng chung.

Nếu lab cấp URL proxy, cập nhật file .env:
- DJANGO_ALLOWED_HOSTS: hostname thật, không có https:// hoặc đường dẫn.
- DJANGO_CSRF_TRUSTED_ORIGINS: origin thật gồm https:// và hostname.
- DJANGO_SECURE_COOKIES=1 cho HTTPS; dùng 0 khi chạy HTTP cục bộ.
Khởi động lại service web sau khi đổi cấu hình.

2. TASK 2 — CHẠY DJANGO DEVELOPMENT SERVER TRONG LAB

Đề muốn ảnh server chạy từ lab Static Pages. Sau khi cài Python 3.12 và
Node 22.12+, có thể chạy web ngoài container để lấy ảnh terminal này.
Các dịch vụ Mongo/Express/Sentiment cần đang chạy:

   docker compose up -d mongo backend sentiment

Trong một terminal khác, cài và build frontend:

   cd server/frontend
   npm ci
   npm run build
   cd ..
   python3 -m venv .venv
   . .venv/bin/activate
   pip install -r requirements.txt
   python manage.py migrate
   python manage.py seed_cars
   python manage.py runserver 0.0.0.0:8000

Nếu service web trong Compose đang dùng port 8000, dừng riêng service đó trước:
   docker compose stop web

Đặt BACKEND_URL=http://127.0.0.1:3030 và
SENTIMENT_ANALYZER_URL=http://127.0.0.1:5050 cho Django chạy ngoài Compose.
Nếu Express có WRITE_API_TOKEN, Django cần BACKEND_WRITE_API_TOKEN cùng giá trị.
Giữ các biến bí mật trong .env, không đưa vào ảnh hay commit.

thư mục .git của clone. Trong repository:

   git push origin main

Task 1: dùng URL thực tế của fork sau khi push thành công.
Không nộp URL repository gốc của IBM thay cho fork của bạn.

Mở tab Actions trên fork, chạy/chờ workflow "Capstone CI".
Workflow kiểm tra Django, build React, chạy test Express và build container.
Task 23: chụp trang run thành công, thấy tên workflow/repository và các job xanh.
Workflow còn chạy ứng dụng thật và tạo artifact dealership-local-evidence gồm
ảnh trình duyệt cục bộ. Tải artifact từ trang run sau khi nó thực sự hoàn tất.
Ảnh localhost trong artifact vẫn cần chụp lại trong lab nếu đề yêu cầu.
Không dùng ảnh file YAML hay log kiểm thử cục bộ thay cho run GitHub.

Có thêm hai workflow chạy thủ công:
- Publish capstone images: build/push 3 image lên GitHub Container Registry.
- Deploy capstone to Kubernetes: deploy bằng kubeconfig được cấp và namespace thật.
